# Редизайн вкладки «Долги» (Pulse Desk) — дизайн-спека

- Дата: 2026-06-14
- Автор: дизайн-сессия (brainstorming)
- Статус: на ревью (концепция утверждена пользователем)
- Артефакт: веб-вкладка Pulse Desk (`#debts`)

## 1. Контекст и постановка

**«Долги» = выигранные, но ещё не полученные призы. То, что должны МНЕ/команде, а не мои обязательства.**
Канал проводит розыгрыш → пользователь (или друзья: пумба, тимон, снейк, вова, мувер) выигрывает → приз ещё у организатора. Это дебиторка «натурой»: *кто мне должен приз, до какого дедлайна забрать, не скам ли источник*.

Источник данных: `GET /api/debts` → `get_debt_board()` ([database/boards.py:281](../../../database/boards.py)) — победы (`is_win=1` или `action_status='claim_prize'`) из каналов, `giveaway_status='pending'`, не закрытые. Закрытие: `claimed` (Забрал), `missed_reply` (Не отписал), `missed` (Не успел), `scam` (Скам).

Параллельно: панель «Obsidian · @Долги» зеркалит заметку `Долги.md` (секции `# @username <split_rule>`, чек-листы `t.me`-ссылок) через `src/pulse_desk/obsidian_debts.py`. Note wins on conflict; синхронизируется только бит «done = claimed».

### Решения сессии
- **Артефакт:** редизайн реальной веб-вкладки (`static/index.html` + `static/js/app-dashboard.js` + `static/js/app-obsidian.js` + `static/app.css`). Без отдельного Obsidian-дашборда.
- **Герой:** гибрид — счётчик призов + ₴-оценка + ближайший дедлайн (опора), ₴ из `estimated_value` где известно.

## 2. Аудит текущей вкладки (база)

Оценки: практичность 6/10, читаемость 6/10, скорость 5/10, масштабируемость 6/10, визуал 7/10.

Ключевые проблемы:
1. Две конкурирующие системы «долгов» стоят стопкой (авто-доска + Obsidian-панель) в разных визуальных языках.
2. KPI — только счётчики; нет денег, нет ближайшего дедлайна, нет «что горит».
3. Самая дорогая потеря — `missed_reply` (выиграл, но не написал организатору в срок) — никак не предотвращается.
4. Карточка из ~5 ярусов → низкая плотность (2–3 на экран), тройные дубли бейджей.
5. Риск-скам не виден заранее, хотя `source-scores` уже считает надёжность каналов.
6. Срочность не управляет сортировкой на уровне экрана; дедлайн спрятан в карточку.

## 3. Цели и не-цели

**Цели**
- Снизить `missed_reply` (главная метрика успеха).
- «Что горит» — за один взгляд.
- «Забрал» — 1 клик / bulk.
- Поднять плотность очереди ×2–3.
- Показать деньги и риск-скам.

**Не-цели (YAGNI)**
- Денежно-первый герой (выбран гибрид).
- Канбан по статусу.
- Обязательное явное поле стоимости/дележа на профиль (опционально, позже).
- Отдельный Obsidian-дашборд.

## 4. Архитектура экрана

Подход: **action-queue, urgency-first** (выбран из 3: A queue / B kanban / C profile-first). Статус — фильтр-сегмент; «люди/дележ» — правая линза.

```
HEADER        Долги · что мне должны        [Скан] [Забрать выбранные · N]
HERO KPI      N призов · ≈₴ к получению · ⏰ ближайший дедлайн · % забрано/30д
SEGMENTS      [Все] [Просрочено] [Сегодня] [На неделе] [Риск]
FOCUS NOW     1–3 горящих (countdown + «написать организатору»)
QUEUE (по сроку, аккордеоны) | LENS (люди/дележ + надёжность источников)
HISTORY       свернуто: забрано/скам + Obsidian Долги.md
```

### Блоки (важность / частота)
| Блок | Цель | Скрыт когда | Mobile | Важн. | Частота |
|---|---|---|---|---|---|
| Header | контекст + bulk + скан | — | 1 строка, bulk → FAB | ср | каждый вход |
| Hero KPI | сколько/на сколько/когда | — | 1 тайл + countdown-чип | крит | каждый вход |
| FOCUS NOW | убить missed_reply/просрочку | нет горящего (≤24ч/просрочка) | на всю ширину | крит | ежедневно |
| Queue | разобрать очередь | пустые группы | 1 столбец, аккордеоны | крит | ежедневно |
| Lens | деньги по людям + риск | <1200px → bottom-sheet | bottom-sheet «Линзы» | ср | 1–2×/день |
| History/Obsidian | архив + дележ | свёрнут по умолчанию | аккордеон в конце | низк | еженедельно |

## 5. Визуальный язык

На существующих токенах «Bold Bento» ([app.css:11](../../../static/app.css)) — без новой палитры. Цвет = срочность, mono = деньги/время, левый таб карточки = состояние.

- Цвета: `--accent #6c4dff` (действия/актив), `--good #16a34a` (забрал/норма), `--warn #e8910b` (скоро/сегодня), `--bad #f5455c` (просрочка/скам), `--info/--muted` (нейтраль). Тёмная тема — парные токены, без хардкода.
- Типографика: Space Grotesk (заголовки/hero 19–34/700), Inter (тело 13–15), JetBrains Mono + `tabular-nums` (₴, дедлайны, countdown).
- Карточка-строка: радиус 12, высота ~58–64px, левый 3px-таб = состояние, плотность 8–12/экран. FOCUS-карточка: радиус 18, `*-soft` фон, крупный mono-countdown.

### Состояния долга
| Состояние | Цвет | Бейдж | Сигнал |
|---|---|---|---|
| Норма (>7д / без срочности) | info/нейтраль | «На неделе»/«Без срока» | таб `--line` |
| Скоро (сегодня/≤48ч) | warn | «⏰ Сегодня · 6ч» | таб warn, фон warn-soft, ≤24ч → FOCUS |
| Просрочка | bad | «🔴 −1д» | таб bad, фон bad-soft, пульс таймера |
| Закрыт/Забрал | good | «✓ Забрал ✅дата» | приглушение, зачёркнут, → История |
| Риск/скам | bad outline | «🛡 риск 0.4» | иконка + полоска надёжности источника |

## 6. Влияние на данные и API (минимальное, фронт-первый)

- `get_debt_board().stats`: добавить `value_pending` (Σ `estimated_value` где есть), `nearest_deadline`, счётчики `overdue/today/soon`, `claim_rate_30d`, `risk_count`. Поля `deadline_state`, `candidate_score`, `estimated_value`, `blocked_reason` уже приходят через JOIN ([boards.py:285](../../../database/boards.py)).
- Надёжность источника на строку: подтянуть source score канала (см. `database/channels.py` source_scores) → поле `source_reliability` для риск-бейджа/сегмента.
- Bulk: либо новый `POST /api/debts/bulk` (массовое `giveaway_status`), либо клиентский цикл по существующему `POST /api/pings/{id}`.
- Obsidian: контракт не меняется. Панель переносится в «Историю»; `split_rule` из `build_snapshot().groups` ([obsidian_debts.py:341](../../../src/pulse_desk/obsidian_debts.py)) питает подпись дележа в линзе.
- Фронт: сохранить/обновить ID-хуки, на которые завязаны обработчики в `app-main.js` (`debts-list`, `debt-profile-tabs`, `obsidian-*`); при смене DOM — синхронно править слушатели. Бампить `CACHE_NAME` в `static/sw.js`.

## 7. Быстрые действия / автоматизация

- 1 клик: ✓ Забрал (строка), ✍ Написать организатору (deep-link + `waiting_result` + напоминание), bulk «Забрать выбранные», свайпы (mobile), сегмент-фильтры, snooze (job `reminders`).
- Авто: группы по `deadline_state`; ₴-агрегат; риск из source score (<0.5 → «Риск»); подбор «Сейчас горит» (≤24ч/просрочено и не закрыто); авто-переход в «Просрочено»; авто-уезд закрытых в Историю; скорость получения за 30д; «дележ» из `split_rule`.
- Меньше ручного: дедлайны парсятся; ссылка/организатор из `link`; ₴ из `estimated_value`; web-«Забрал» → ✅дата в Obsidian (`mark_link_done`).

## 8. План внедрения (по коммитам, низкий риск)

- **P0** — новый layout `index.html` + строки-карточки + сегменты + группировка по сроку в `renderDebts` (чистый фронт; `deadline_state`/`priority` уже есть).
- **P1** — Hero-гибрид (₴-агрегат в `get_debt_board().stats`) + FOCUS NOW (клиентский фильтр ≤24ч/просрочка).
- **P2** — риск-сегмент + линза «Надёжность источников» (source score в строку).
- **P3** — bulk-выбор + свайпы (mobile) + горячие клавиши (J/K навигация, C=claimed, W=написать).
- **P4** — Obsidian-панель → свернутая «История» + линза «Люди/дележ» (`split_rule`).

Каждый шаг — отдельный коммит. Фронт-первый; бэк добавляется инкрементально. После каждого шага: `py_compile`/`import main` + `node --check` изменённых JS + ручная проверка вкладки.

## 9. Метрики успеха (проверка через неделю)

- ↓ доля `missed_reply` — главный сигнал.
- ↓ кликов до «Забрал»; ↓ субъективного времени «понял состояние».
- Не растёт доля `scam` после claim (помогает ли риск-бейдж).
- Верность ₴-агрегата и группировки по срокам на реальных данных.
- Mobile: удобство свайпов/аккордеонов.
- Obsidian sync цел: toggle / append / ✅дата.

## 10. Риски

- Смена DOM ломает обработчики `app-main.js` → править слушатели в том же коммите.
- ₴-агрегат вводит в заблуждение при редком `estimated_value` → префикс «≈» + подпись «оценка по N из M».
- Source score не у всех каналов → риск-бейдж только при наличии score; иначе нейтрально.
- PWA-кэш отдаёт старый шелл → обязательный бамп `CACHE_NAME`.

## 11. Вне области

Денежно-первый герой; канбан; явное поле стоимости/дележа на профиль; отдельный Obsidian-дашборд; изменение правил sync (note wins сохраняется).
