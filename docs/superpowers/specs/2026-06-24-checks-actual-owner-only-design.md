# Чеки: только актуальные, только владелец

**Дата:** 2026-06-24
**Статус:** утверждается

## Проблема

«Чеки» — это перепосты CryptoBot чек-ссылок (`чек на 5 TON`, `мультичек`),
детектятся в каналах и сохраняются как пинги с `is_check = 1`
(`ping_pipeline.process_ping_message`). Сейчас:

1. **Не видны в веб-приложении.** В `type-filter` (`static/index.html`) нет
   опции «check», хотя бэкенд уже умеет `chat_type="check"`
   (`database/pings.py:234`). Видны только через бота `/checks`.
2. **Копятся старые.** Чек забирают за секунды-минуты; через час ссылка почти
   наверняка мертва. Старые чеки засоряют выдачу.
3. **Доступны любому.** `/api/pings` открыт и для роли `viewer`
   (`Depends(get_current_role)`), поэтому viewer может вытащить чеки.
4. **Ложные срабатывания.** Регекс `(?<!\w)(?:чек|мультичек)\w*`
   (`giveaways.py:_check_regex`) ловит и глагол «чек**ать**/чек**ни**/чек**аю**»
   — спам.

## Требования

- R1. Чеки видны в веб-приложении — отдельный вход в раздел.
- R2. Чеки доступны **только владельцу** (роль `admin`); viewer их не видит и
  не может получить.
- R3. В выдаче — **только актуальные**: чеки, найденные ≤ 60 минут назад.
  «Только новые» = просто свежие по времени, без фильтра по статусу
  прочитанности.
- R4. Старые чеки (> 60 минут) **удаляются из БД** фоновой задачей.
- R5. Детектор чеков **не считает чеком глагол** «чекать/чекни/чекаю/…».
  Существительное «чек/чека/чеки/чеков/мультичеки» по-прежнему матчится.

## Дизайн

### 1. Детектор: именные окончания вместо `\w*` (R5)

`giveaways._check_regex` строит на каждое ключевое слово паттерн
`(?<!\w)(?:слово)\w*`. Суффикс `\w*` жадно цепляет глагольные окончания.

Замена `\w*` на необязательный whitelist русских **именных** окончаний с
кириллической границей:

```
(?<!\w)(?:<стем>)(?:ами|ах|ам|ов|ом|а|у|е|и)?(?![а-яё])
```

Окончания — длинные первыми (чтобы `ами` матчилось раньше `ам`).
Граница `(?![а-яё])` запрещает продолжение кириллицей (глагол), но разрешает
цифру/латиницу/пробел/знак, поэтому «чек100грн» матчится.

Трассировка:
- `чек` / `чека` / `чеки` / `чеков` / `мультичек` / `мультичеки` → матч.
- `чекать`: `чек`+`а` → далее `т`∈[а-яё] → граница падает; `чек`+∅ → далее
  `а`∈ → падает ⇒ **нет матча**.
- `чекни` / `чекнуть` / `чекаю`: аналогично ⇒ нет матча.
- `человечек`: `(?<!\w)` падает (перед `чек` стоит `е`) ⇒ нет матча.

Лимит: окончания кириллические и заточены под «чек». Для нестандартных
keyword (например латинских) матчится только голый стем — приемлемо, т.к.
дефолт `CHECK_KEYWORDS=чек,мультичек`.

### 2. Видимость в вебе — admin-only чип (R1, R2)

- Новый quick-filter чип `💸 Чеки` в `#quick-filters` (`static/index.html`),
  класс `admin-only` (как `#read-all-btn`), `data-quick="check"`. Клик ставит
  `type-filter=check` и грузит ленту (обработчик `data-quick` уже есть в
  `app-pings.js`).
- В сам `<select>` опцию **не добавляем** — чтобы viewer не видел даже пункта.
- Чип скрыт у viewer на клиенте (`admin-only`) И закрыт на сервере (часть 3).

### 3. Server-side гейт владельца (R2)

В `routers/pings.py::read_pings`: до выдачи, если запрошен `chat_type == "check"`
и текущая роль ≠ `admin` → `HTTPException(403)`. Берём роль из уже
подключённого `Depends(get_current_role)` (сейчас результат отбрасывается в `_`
— связать с переменной).

### 4. Только актуальные — окно свежести в выдаче (R3)

Источник истины для видимого — фильтр запроса, не лаг очистки.

- `_build_pings_filters` получает новый параметр `detected_after: Optional[str]`
  → `WHERE detected_at >= ?`.
- `read_pings`: при `chat_type == "check"` подставляет
  `detected_after = now - CHECK_FRESH_MINUTES` (UTC-isо, как `now_iso`).
- Бот `bot_service.render_checks` (`get_pings(chat_type="check")`) — тот же
  отсёк по времени, для консистентности.

### 5. Удаление старых из БД (R4)

Новая `database.maintenance.purge_stale_checks(minutes=60) -> int`:

```sql
-- сначала FTS (триггеров нет, как в delete_ping)
DELETE FROM pings_fts WHERE rowid IN (
  SELECT id FROM pings
  WHERE is_check = 1 AND is_favorite = 0 AND is_win = 0
    AND detected_at < :cutoff
);
DELETE FROM pings
  WHERE is_check = 1 AND is_favorite = 0 AND is_win = 0
    AND detected_at < :cutoff;
```

**Защита:** не трогаем `is_favorite = 1` и `is_win = 1` — чек, который владелец
сохранил в избранное или который оказался победой, ценен. Удаляем только
«чистые» эфемерные чеки.

Вызов в cleanup-блоке `loops.auto_scan_loop` (рядом с `cleanup_old_data`,
`loops.py:256`); счётчик добавляется в `record_app_event("maintenance", …)`.

### 6. Конфиг

`CHECK_FRESH_MINUTES: int = 60` в `pulse_desk/config.py` (+ строка в
`.env.example`). Используется и окном выдачи, и `purge_stale_checks`.

## Поток данных

```
скан → process_ping_message → is_check_text (фикс R5) → save_ping(is_check=1)
веб: чип(admin) → /api/pings?chat_type=check
       → гейт роли (403 для viewer) → get_pings(detected_after = now-60м)
бот: /checks → render_checks → get_pings(chat_type=check, detected_after=now-60м)
фон: auto_scan_loop → purge_stale_checks(60) → DELETE pings+fts (щадя fav/win)
```

## Граница / нюансы

- **Лаг очистки.** `purge_stale_checks` дёргается раз в scan-интервал (~15 мин),
  поэтому в БД чек может прожить до ~1ч15м. Но выдача (веб + бот) строго режет
  по ≤60 мин ⇒ пользователь видит ровно час. Очистка = гигиена хранилища.
- **FTS-консистентность.** Удаляем строки `pings_fts` до строк `pings` по
  `rowid = pings.id`, как `delete_ping`. `ping_mentions`/reminders уходят по
  FK-cascade.
- **Favorite/win-чеки** остаются в БД и попадают в обычную ленту (не check),
  что верно — они уже не «эфемерный чек».

## Тестирование

- `tests/test_checks.py`: добавить — `is_check_text` **False** для «чекать»,
  «чекни», «чекнуть», «чекаю», «зачекать»; по-прежнему **True** для
  «чека/чеки/чеков/мультичеки».
- `purge_stale_checks`: удаляет чек с `detected_at` старше окна; **не** удаляет
  свежий, `is_favorite=1`, `is_win=1`; чистит `pings_fts`.
- `read_pings`: viewer + `chat_type=check` → 403; admin → ок.
- `_build_pings_filters`: `detected_after` даёт `detected_at >= ?`.

## Вне рамок

- Реальная live-проверка «забран ли чек» дёрганьем CryptoBot-ссылки (риск
  FloodWait/бана) — не делаем.
- Авто-redeem чеков — не делаем.
- Отдельная страница/вкладка «Чеки» с собственной вёрсткой — переиспользуем
  существующую ленту пингов.
