# Инструкция по запуску Pulse Desk Dashboard

Единая точка входа. Один процесс Pulse Desk поднимает всё: Telegram-watcher,
бота, крипту, аналитику — и спавнит Discord-бота как дочерний процесс.
Управление — в браузере на `http://127.0.0.1:8000`, вкладка **Сервисы**.

---

## 0. Что нужно один раз

| Требование | Проверка |
|---|---|
| Python 3.11+ | `python --version` |
| Node.js 20+ (для Discord-бота) | `node --version` |
| Файл `.env` с токенами (см. `.env.example`) | должен лежать в корне проекта |
| Discord-бот: свой `.env` + `node_modules` | в его папке |

---

## 1. Первый запуск (разовая настройка)

```powershell
cd "D:\Главная папка!!\telegram_ping_watcher"

# создаст .venv, поставит зависимости, запустит
.\run_local.ps1
```

Если venv уже есть и зависимости стоят:

```powershell
.\run_local.ps1 -SkipInstall
```

Открой `http://127.0.0.1:8000`, введи **ADMIN_TOKEN** из `.env`.

---

## 2. Обычный запуск (каждый день)

```powershell
cd "D:\Главная папка!!\telegram_ping_watcher"
python main.py
```

Готово, когда в консоли `Application started`. Дашборд: `http://127.0.0.1:8000`.

---

## 3. Подключить Discord-бота к дашборду

Бот управляется из вкладки **Сервисы**. Манифест уже создан
(`config/services.json`) и указывает на папку бота.

1. **Включи веб-панель бота** — в его `.env`:
   ```env
   WEB_ENABLED=true
   WEB_HOST=127.0.0.1
   WEB_PORT=8080
   ```
   Нужно для встроенной панели в iframe и для индикатора health.

2. Открой дашборд → вкладка **Сервисы** → у `discord-bot` нажми **Старт**.
   - статус станет `работает`, появится PID, аптайм, health = OK;
   - кнопка **Логи** — поток вывода бота;
   - кнопка **Панель** — панель бота прямо внутри дашборда.

3. Когда убедился, что стартует стабильно — включи автоподъём.
   В `config/services.json`:
   ```json
   "autostart": true
   ```
   Теперь бот поднимается сам при старте Pulse Desk.

## 4. Автозапуск при включении ПК

Один раз зарегистрировать автозапуск (при входе в систему, скрыто):

```powershell
.\scripts\install_autostart.ps1
```

Скрипт сам выбирает способ:
- **с правами админа** → задача Task Scheduler (с перезапуском при сбое);
  проверить: `Start-ScheduledTask -TaskName PulseDashboard`;
- **без админа** → ярлык в папке автозагрузки (per-user, без перезапуска);
  проверить: `& .\scripts\start_dashboard.ps1`.

Проверить, что ярлык на месте:
```powershell
Test-Path "$([Environment]::GetFolderPath('Startup'))\PulseDashboard.lnk"
```

Что делает `start_dashboard.ps1` при логине:
1. ждёт сеть (до 30 с);
2. поднимает Pulse Desk скрыто (`pythonw`, без консоли);
3. ждёт ответ `/api/health` (до 40 с);
4. открывает дашборд окном-приложением (Edge/Chrome `--app`).

Убрать автозапуск:

```powershell
.\scripts\uninstall_autostart.ps1
```

Запустить руками без регистрации:

```powershell
.\scripts\start_dashboard.ps1            # поднять и открыть окно
.\scripts\start_dashboard.ps1 -NoOpen    # без окна браузера
```

## 5. Остановка

| Что | Как |
|---|---|
| Discord-бот | вкладка **Сервисы** → **Стоп** |
| Весь дашборд (ручной запуск) | `Ctrl+C` в консоли |
| Дашборд из автозапуска | `Stop-ScheduledTask -TaskName PulseDashboard`, затем закрыть процесс `pythonw` в Диспетчере задач |

При штатной остановке Pulse Desk сам гасит дочерние сервисы (Discord-бот).

## 6. Проверка, что всё работает

```powershell
# тесты
.\.venv\Scripts\python.exe -m unittest discover -s tests

# приложение импортируется и роутеры регистрируются
.\.venv\Scripts\python.exe -c "import main"

# здоровье на лету (когда запущено)
curl http://127.0.0.1:8000/api/health
```

## 7. Если что-то не так

| Симптом | Причина / фикс |
|---|---|
| Вкладка **Сервисы** не видна | нужен **admin**-токен (не viewer) |
| `discord-bot` → `ошибка (стоп)` | проверь `cwd` в `config/services.json` и `node --version`; смотри **Логи** |
| health = `нет`, панель пустая | у бота не включён `WEB_ENABLED=true` или занят порт 8080 |
| «Нет управляемых сервисов» | нет `config/services.json` — скопируй из `config/services.example.json` |
| Автозапуск не сработал | `Get-ScheduledTask PulseDashboard`; смотри `logs\app.log` |
| Порт 8000 занят | смени `PORT=` в `.env` |
